# message-delivery-playground

외부 시스템 연동 시 발생하는 메시지 유실/중복/장애 전파 문제를 **Transactional Outbox 패턴**으로 해결하는 과정을 단계적으로 보여주는 프로젝트.

"동기 호출 → MQ 직접 발행 → Outbox 도입 → 엣지 케이스 해결"까지, 코드가 진화하는 과정을 **git 태그 + 시나리오별 테스트 + 장애 스토리**로 구성했습니다.

## 왜 만들었나

주문 서비스에서 알림 발송을 동기로 호출하다 외부 장애가 전파된 경험이 출발점입니다.
"MQ를 도입하면 해결되는 거 아닌가?"라는 질문에서 시작해, 실제로는 MQ를 도입해도 메시지 유실/중복/순서 역전 등 수많은 엣지 케이스가 존재한다는 것을 시나리오별로 재현하고 해결합니다.

## 기술 스택

- Java 21, Spring Boot 3.4
- MySQL, RabbitMQ
- Testcontainers (테스트 환경)

## 프로젝트 따라가기

아래 시나리오 맵에서 궁금한 항목을 클릭해서 스토리와 교훈 확인, 테스트 실행으로 재현할 수 있습니다.

## 실행 방법

### 사전 조건

- JDK 21+
- Docker (Testcontainers가 MySQL 컨테이너를 자동으로 띄웁니다)

### 테스트 실행

```bash
# 전체 테스트
./gradlew test

# 특정 시나리오만
./gradlew test --tests "S00_1_ContagionTest"
```
